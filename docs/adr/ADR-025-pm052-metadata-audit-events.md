# ADR-025：PM-052 关键元数据变更审计事件

- **状态：** 提案，等待用户对下列范围及数据库迁移设计作出明确批准；当前 worktree 尚未修改产品代码或 schema。
- **日期：** 2026-10-30
- **路线图：** PM-052（actor/request/time 可追踪；不记录 token、路径或相片明文）。
- **依赖：** PM-041/043 标签写入；PM-044/045 虚拟相册；PM-046 收藏；PM-047 评分；PM-051 Web 单项批量调用。

## 背景

架构文档提出概念 `audit_logs(actor, action, resource, outcome, request_id, created_at)`，但现有 `events` 与各 P2P 同步事件日志不是 HTTP 审计记录：它们不关联本地请求 ID 或当前认证主体。Node 已有请求 ID，但目前可直接采用调用方 `X-Request-ID`；当前授权主体为 `local-admin`，不能据此声称识别了具体人或设备。

## 建议方案（推荐，需批准）

1. **本地审计表与字段。** 追加迁移 `0013_metadata_audit_events`，不改写历史迁移。最小字段为递增记录 ID、actor、action、resource type/opaque resource ID、outcome、validated request ID、Node 生成的 UTC 时间；只建获批用途所需索引。只提供内部写入/测试读取，不新增 HTTP 读取 API、UI、导出或 P2P 同步。
2. **审计范围（推荐）。** 记录经认证且通过图库授权的本地写请求：单项标签添加/移除、收藏设定、评分设定/清除，以及虚拟相册创建、成员添加/移除、删除/恢复（现有 API 无相册改名端点）。PM-051 批量操作按逐资产 HTTP 请求形成多条记录。不记录读取、预览/下载、入站 P2P 投影事件或配对信任/授权 grant 等控制面变更；这些需另行批准。
3. **actor 与 outcome（推荐）。** `actor='local-admin'` 只表示当前认证主体类别，不识别人名、设备或 peer。仅对被授权且成功提交的写请求记录 `applied`、`unchanged` 或幂等重放 `replayed`；不记录未认证、授权拒绝、验证失败、业务失败或未提交的服务端错误。在上述批准范围内，每个已授权且成功提交的写请求各记一条审计记录，不含业务值或 HTTP 错误正文。
4. **事务与失败闭锁。** 每条业务变更与其审计行必须在同一 SQLite 写事务中提交；审计插入失败时业务变更必须回滚/不生效。不能在业务提交后才做 best-effort 日志。需在实际 repository/service 事务边界证明此保证；可按需重构入口，但不得弱化原有 outbox/同步原子性。
5. **请求 ID（推荐规则）。** 只接受恰好一个原始 `X-Request-ID` header，且值完整匹配 `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`（1–64 ASCII 字符，不 trim、不接受空白、逗号或 CR/LF）。通过 `rawHeaders` 识别重复字段；缺失、无效或重复时忽略来值并生成 Node UUID，继续处理请求。选定的唯一 ID 必须在响应头与审计行一致；不回显或存储被忽略的原始值。它仅作关联字段，不作为 actor 或授权凭证。
6. **隐私、完整性与保留。** 不存 token、其他请求头/请求体、路径、文件名、标签/评分/收藏值、照片字节或媒体明文。只存不透明资源 ID；它们仍可关联本地库/资产/相册，故表仅本地保存，不提供网络查询/导出。推荐无限期保留且不自动删除，以免隐式丢失审计记录；明确接受本地数据库无界增长，后续保留/清理策略需另行批准。所谓“append-only”仅是应用层不提供更新/删除路径；不抵抗可直接修改 SQLite 文件的本机管理员，不承诺防篡改、签名链或防篡改证据。
7. **兼容与恢复。** 迁移为 append-only 0013；迁移前必须有可验证备份，并测试失败原子性与重启持久化。不提供破坏性“降级迁移”；旧版遇到未知 schema version 按现有策略拒绝启动，回滚依赖恢复迁移前备份。此 ADR 不授权在生产图库执行迁移。

## 待用户明确批准

以下均为建议默认值，须由用户明确接受或修改后，才能实现数据库变更：

- **范围/失败：** 是否仅覆盖上列标签、收藏、评分、虚拟相册写入，并排除配对/授权 grant、未认证/拒绝/验证失败/业务失败请求。
- **actor：** 是否接受 `local-admin` 只代表认证主体类别，不具备个人或设备级归因能力。
- **请求 ID：** 是否批准精确 ASCII 正则 `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`；重复、缺失或非法值生成 UUID、且相同选定 ID 写入响应头和数据库。
- **资源隐私：** 是否接受本地表保存不透明 resource IDs（仍可稳定关联库/资产/相册），但不提供网络读取/导出。
- **保留与完整性：** 是否接受无限期保留（无界本地磁盘增长、无自动清理）以及仅应用层 append-only（本机数据库文件所有者仍可篡改）；如不同意，需先批准准确的有限保留/清理或防篡改需求。
- **原子性/兼容：** 是否要求审计写失败时业务变更必须回滚，并同意追加 `0013`、旧版本拒绝未知 schema、回滚依靠迁移前备份恢复；这些不是生产迁移授权。

## Fail-first 验收计划

先让测试在实现前失败：迁移追加/既有迁移不可变、迁移失败原子性、重启持久化、受控 UTC 时钟、actor 语义；覆盖 request ID 的正则边界、缺失/空白/非法/重复 rawHeaders，确认生成 ID 在响应头与审计行完全一致；批准范围内各写路由的 action/resource/outcome 与业务提交原子一致；强制审计插入失败并证明业务写未提交；读取及明确排除的失败请求不写日志；重复/idempotent 结果；直接查询原始 DB 确认 token、路径、文件名、元数据值与媒体明文不落库。随后运行 Node Agent 定向测试，以及根级 install/lint/typecheck/test/contracts/build；不改 P2P 协议时不需双节点同步测试。

**实施门槛：** 在用户明确批准上述 ADR 与迁移方案前，不实现迁移、审计存储或任何 API/协议变化；生产迁移、push、merge、release/deploy 始终需要各自明确授权。
