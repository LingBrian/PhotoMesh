# ADR-015：Node 服务端标签持久化与 SQLite 迁移（PM-041）

- **状态：** 用户已批准该设计（2026-10-27）；仅批准隔离分支中的 PM-041 实现与测试，不包括生产数据库迁移、push、merge 或 release。
- **日期：** 2026-10-27
- **对应路线项：** PM-041；后续依赖 PM-042（标签事件同步）、PM-043（Web 改用 Node API）。
- **相关决策：** ADR-002（标签集合以元素级 add/remove 合并）、ADR-014（当前 Node HTTP API 契约）。

## 背景与现状

当前 Gallery Web 将 `tags` 与虚拟相册 `albums` 写入浏览器 IndexedDB，键由节点 API URL 与 `libraryId` 组成。编辑器现有行为是给单个资产新增一个去空白标签；没有服务端标签 API，也没有 P2P 标签事件。服务端图库同时可能列出本地 `assets` 行和远端 `sync_asset_projection` 行，因此标签不能只外键关联本地 `assets` 表。SQLite 的迁移账本按校验和保护既有迁移；对已有非空数据库应用待处理迁移前必须先完成备份；旧版二进制遇到未知 migration ID 会拒绝启动，防止静默降级。

## 目标与非目标

**目标：** 在单个 Node 上为授权图库的资产提供可靠的标签状态读取、幂等增删和 SQLite 持久化；API 由当前 Node 管理员 Bearer 及图库授权保护；重启后状态不丢失。

**非目标：** PM-041 不更改 Web UI、不导入浏览器 IndexedDB、不实现 P2P 标签同步/冲突合并、不实现虚拟相册服务端模型，也不修改原图、资产索引语义或旧迁移。Web 接入与本地标签导入留给 PM-043；跨节点事件与 OR-set 语义留给 PM-042。

## 决策

### API 与幂等语义

1. 为 `GET /v1/assets` 的每个可见条目增加 `tags: string[]`；无标签时返回空数组。使用当前分页结果的批量查询，不为每个资产额外发起一次 HTTP/SQL 查询。旧客户端忽略新增响应字段即可。
2. 新增 `PUT /v1/libraries/{libraryId}/assets/{assetId}/tags/{tag}` 以幂等添加单个标签，和 `DELETE` 同路径以幂等移除单个标签。两者均返回 `204`；重复添加或删除不存在的标签不产生重复行或错误。单元素操作与现有 Web “新增标签”行为一致，也为后续 PM-042 的元素级事件留下映射空间。
3. 标签暂按当前客户端语义处理：去除首尾空白、区分大小写；不静默重命名或折叠标签。服务端限制单标签 UTF-8 长度不超过 128 字节、每资产最多 64 个标签，超限返回 `400 invalid_request`。现有浏览器端没有相同上限，PM-043 迁移时必须检测超限项、保留原 IndexedDB 数据并给出明确结果，不得静默丢弃。
4. 所有新路由与列表标签字段均受 Node 管理员 Bearer 及指定 `libraryId` 的当前图库 ACL 保护；不授权时保持当前 `403 forbidden` 行为，资产不存在/不在该图库或不可见时按现行防枚举约定返回 `404 not_found`。成功响应不泄露路径或管理凭据。请求仍由通用中间件提供 `X-Request-ID`。

### SQLite 迁移

1. 追加新迁移 `0005_asset_tags`，不修改 `0001`–`0004` SQL/checksum。新建 `asset_tags(library_id, asset_id, tag, created_at)`；主键为 `(library_id, asset_id, tag)`，按二进制、区分大小写语义唯一，并建立图库/资产读取索引。
2. 不对 `assets` 建单表外键，因为资产也可能只存在于 `sync_asset_projection`。写入前由服务校验资产当前可见；表级插入保护同时确认其属于本图库的本地资产或未 tombstone 的同步投影。tombstone 隐藏资产时不物理删除标签；显式恢复后原标签仍可见。原图/外部目录绝不触碰。
3. 迁移只建空表、索引和必要约束，不扫描或改写旧资产、浏览器数据或事件日志。当前启动器对非空数据库在应用 pending migration 前执行 SQLite 备份；备份失败则启动失败并拒绝迁移。生产数据库不在本实现或测试中打开。

### 兼容、回滚与数据保护

- 新响应字段和新路由对旧客户端是增量扩展；没有标签 API 的旧客户端可继续工作。PM-041 结束时 Web 仍使用原 IndexedDB，服务端标签只由明确调用新 API 的客户端产生。PM-043 应以幂等逐标签添加方式合并旧浏览器标签；不得以旧缓存覆盖服务器已有标签，虚拟相册仍保持独立范围。
- PM-042 前，标签只持久存在于写入该标签的 Node，不声称跨节点已同步。后续同步必须显式映射为元素级 add/remove 事件，并为既有服务端标签制定初始投影策略。
- 迁移账本拒绝旧二进制读取未知 `0005`。因此不能只回退程序版本：回滚须停止 Agent 并恢复迁移前备份。恢复旧库会丢失迁移后新写入的服务端标签；若这些标签已有价值，应优先向前修复，或在回滚前用授权 API 导出并另行确认恢复办法。不得静默降级、删除表或声称旧二进制可直接复用新数据库。生产迁移须在独立审批、备份校验和恢复演练后进行。

## 验收与验证

- Migration 测试验证新库创建、旧库追加 `0005`、既有 checksum 未变、触发器接受本地/活动投影资产并拒绝越库/不存在/已 tombstone 资产；备份缺失或失败时不应用迁移。
- Repository 测试验证图库隔离、唯一标签、确定排序、add/remove 重复调用无副作用；临时文件 SQLite 关闭并重开后标签仍在。测试只用隔离内存库/临时文件，不读取用户数据。
- HTTP 契约与集成测试覆盖公开列表字段、403/404/400、标签增删、重复请求、`X-Request-ID` 和管理员/图库 ACL；旧 API 行为与 `GET /v1/assets` 既有游标语义保持不变。
- 验证记录（2026-10-27，PM-041 隔离 worktree）：`pnpm install --frozen-lockfile`、`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm contracts:check`、`pnpm build` 全部通过；Node Agent 190 项测试、contracts 12 项测试通过，Node Agent 总覆盖率 91.67% 行/83.73% 分支。
- 本实现未执行生产数据库迁移，也未宣称 PM-042/043 或实机验收完成。

## PM-043 Web 集成决策（2026-10-28）

- 用户已批准继续推进 PM-043 至 PM-100；本节记录 PM-043 的具体集成边界。Web 只从当前经过管理员 Bearer 与图库 ACL 授权的 Node `GET /v1/assets` 读取标签，且仅当 `/v1/health` 宣告 `assetTags` 能力时提供编辑。新增标签沿用单元素 `PUT`；只有收到 `204` 后才更新服务端标签视图。虚拟相册仍单独保存在浏览器 IndexedDB。
- 旧浏览器标签在相应资产页加载时逐资产、逐元素幂等 `PUT` 合并，绝不整组覆盖 Node 状态；尚未加载的资产会保留在本地缓存，直至其页加载后再导入。旧 `tags` store 保持不变；新增的 `tag-imports` store 保存每资产已成功导入的标签集合，且每次用单个 IndexedDB readwrite transaction 读取、合并、写回，避免多标签页并发覆盖标记；后续仅合并新增加的本地旧标签，并避免重连把已导入、后来由用户删除的标签复活。Node REST 写入使用节点持久化身份 `identity.peerId` 作为事件作者（不同管理员 Bearer 在同一 Node 上共用此写入身份），因此标记按节点源/图库/资产共享而非按浏览器 token 分割。该 API 未向 Web 暴露稳定节点身份字段；若在同一源地址复用库 ID 并替换节点身份，自动识别不在 PM-043 范围内，旧 `tags` 缓存仍保留以便后续人工恢复。浏览器 IndexedDB 升至版本 2 仅新增 store，不删除或重写已有标签；导入失败/超限/标签无效时保留并显示本地旧标签及重试提示。
- 本切片不新增 Node 路由、SQLite migration、同步协议或生产数据操作。对失败/离线请求不作乐观成功；128 UTF-8 字节与服务端每作者 64 标签上限由本地预检及 Node 权威校验共同保障。
- PM-043 验收包含：授权 API 写入、服务端已有标签保留、刷新后从 Node 恢复、旧缓存仍存在、无效或超长旧标签保留且明确提示、HTTP 拒绝/网络失败不改变标签视图或关闭编辑器。
- 验证记录（2026-10-28，PM-043 隔离分支）：`pnpm install --frozen-lockfile`、`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm contracts:check`、`pnpm build` 均通过；Node Agent 241 项测试通过，行覆盖率 92.05%、分支覆盖率 83.76%；完整 Playwright 20 项通过。未修改 Node/SQLite schema，未执行生产迁移。
