# 预发布构建与发布流程

本流程只发布 `alpha`、`beta`、`rc` 预发布版本。它不会创建 Stable 版本、移动稳定版标签或部署服务。

## 进入 main 的要求

阶段分支通过 PR 合入 `main`。`.github/workflows/ci.yml` 在 PR 上运行 lint、TypeScript、Vitest、Flutter、OpenAPI/JSON Schema、Playwright 10 万条查询、构建和 Windows Tauri 原生检查；`required-ci` 汇总门禁。预发布工作流只能从 `main` 手动触发。

## 运行预发布

在 GitHub Actions 选择 **Build and publish prerelease**，使用 `0.x.y-rc.n`、`0.x.y-beta.n` 或 `0.x.y-alpha.n` 版本。也可从仓库根目录运行：

```powershell
gh workflow run prerelease.yml --ref main -f version=0.1.0-rc.1
```

工作流先运行 `pnpm release:gate`。它会执行自动测试、100k 同步与完整性模拟、双节点断线恢复、2 GiB NAS 资源模拟、数据库备份/恢复、ACL 矩阵、Playwright P95、依赖审计，并生成机器可读报告、SBOM、Changelog、SHA-256 清单和源码包。门禁为 `blocked` 或任何平台构建失败时，不会创建 GitHub Release。

门禁通过后，CI 构建 Web 静态包、Linux x86_64 NAS Docker 镜像、Android APK 和 Windows Tauri 安装包。安装包使用该次运行生成的一次性签名身份；证书随产物发布，GitHub 另生成构建来源证明，所有产物附 SHA-256 校验值。预览签名不是商业受信任发布者签名，Android 的密钥每次构建变化，安装新候选前需卸载旧预览。

## 证据边界

自动发布候选的 100k 文件/事件数据是合成测试数据，单文件内容很小；Docker NAS 使用 x86_64 主机限制为 2 GiB 内存。它们验证同步逻辑、索引规模和核心服务资源行为，不等同于 100k 真实照片/视频的吞吐基准或 ARM64 NAS 实机结果。报告须保留这些限制；如果要求的实机或真实媒体证据缺失，门禁应继续阻止预发布。

## Stable 边界

Stable 需要另行完成人工验收、正式代码签名和发布审批。预发布工作流的版本校验只接受带 `alpha`、`beta` 或 `rc` 后缀的版本。
