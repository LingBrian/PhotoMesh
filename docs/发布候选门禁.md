# 发布候选自动门禁

`pnpm release:gate` 仅生成本地候选包，不发布 GitHub Release、不推送镜像、不修改 Stable 标签。候选只有所有自动检查和实测证据均通过时才会标成 `ready-for-human-review`；任何失败或缺少的实测均为 `blocked`。

## 执行

```powershell
$env:PHOTOMESH_CANDIDATE_ID = "0.1.0-rc.1"
$env:PHOTOMESH_RELEASE_EVIDENCE = "D:\release-evidence.json"
# 可选：Flutter SDK 的 bin 目录（若未加入 PATH）
$env:PHOTOMESH_FLUTTER_BIN = "C:\tools\flutter\bin"
pnpm release:gate
```

候选产物写到 `artifacts/release-candidates/<candidate-id>/`，包括 `release-report.json`、100k 查询性能 JSON、输入的机器测量证据（若存在）、CycloneDX SBOM、Changelog、SHA-256 校验清单及源码归档（Windows 为 ZIP，其他平台为 TAR.GZ）。门禁报告每项包含状态、耗时、命令、原始输出尾部或补证原因，可按失败项定位。失败退出码为 1，产物仍保留供审核。

## 必需实测证据

将 `docs/release-evidence.example.json` 复制到本机非仓库路径，填入真实测试记录。占位值不能通过。应由测试系统记录 100k 数据集首次、增量及断网恢复三轮结果；从网络恢复且双方可达到首个事件 ACK 的秒数；实际 2GB ARM64 NAS 型号、内存峰值/余量；完整 100k 文件 SHA-256 对比及源未变；迁移前备份/隔离恢复证明；所有者、管理员、家庭成员、访客、撤销及不可信设备权限矩阵。不要在证据文件中放照片、令牌、密钥或用户路径。

100k 查询门禁会运行 Playwright 真实 Node API/SQLite 用例：100,000 条元数据、1,000 次分页查询采样，要求 API P95 严格小于 1,000ms。报告包含 P50/P95/P99/max、样本分布和执行主机信息。它不替代不同硬件上的低负载与冷/热缓存发布测量。

双节点 Compose 脚本验证独立 SQLite、配对、增量事件、离线后补同步、节点重启和本地原图 SHA-256；当前小型故障冒烟不冒充 100k 文件三轮验收。100k 同步及 2GB ARM64 NAS 没有真实结果时必须保持阻断。

## 人工发布边界

`node scripts/release-gate.mjs --package-only` 可只组装标为 blocked 的空证据模板包；该模式不能通过门禁。`ready-for-human-review` 仅表示候选材料具备提交维护者审核的条件，不等于 Stable 批准。此脚本和 GitHub 工作流没有发布步骤；Stable 发布、签名密钥使用、推送和版本标签仍须人工确认并执行。
